# Обслуживание OKF-бандла

Правило и формат отказа — в блоке `Knowledge bundle` в `AGENTS.md`. Здесь — механика, команды и сигналы. Правило подпёрто механикой, потому что само по себе не работает (в соседнем проекте за ~200 коммитов бандл не обновился в потоке ни разу):

| Слой | Когда срабатывает | Что делает |
|---|---|---|
| `Stop`-хук (`scripts/okf/stop_guard.py`) | сессия закончила работу | **блокирует завершение**, если изменения относительно `__OKF_BASE_REF__` задели код, покрытый концептами, а сами эти концепты не обновлены; об одном и том же наборе концептов — раз за сессию |
| `SessionStart`-хук | начало сессии | одна строка про общий дрейф — фон, а не принуждение |
| CI: `okf-gate.yml` (`drift.py --gate`) | каждый PR и пуш в `__OKF_BASE_REF__` | то же правило, что у Stop-хука, для любых коммитов — с GitHub, руками, из других агентов |
| CI: `validate_bundle.py` | каждый пуш | бандл обязан оставаться валидным OKF |
| Скилл `okf-guardian` | вручную / `/loop` | сеть для того, что прошло мимо, и для `EXPIRED` |

Stop-хук и CI считают концепт обработанным, когда его текст изменён в этой ветке: правка одного концепта не прикрывает другой, пробелы и пустые строки не в счёт. Stop-хук не блокирует, если выставлен `OKF_SKIP=1`, детектор не смог посчитать дрейф, блокировка уже была в этом ходу или об этом наборе концептов он уже напоминал в этой сессии. Отказ `okf: n/a — <причина>` принимают оба: причина не короче 8 символов, покрывает файлы только своего коммита, а решение остаётся в истории git.

Концепт, обновлённый вместе с правкой его источника (в том же PR или `docs(okf)`-коммитом сразу поверх кода), `drift.py` помечает **◐** (`--json`: `refreshed`), но из STALE не убирает: правка, тронувшая концепт, часто упускает часть изменения, и скрытая метка спрятала бы этот дрейф. `--branch` отвечает на вопрос «какие концепты задела эта ветка», ◐ — «какие из них ветка уже обновила»; по ней Stop-хук решает, что осталось. На рефреше начинай с непомеченных, ◐ — проверь на полноту.

```bash
python3 scripts/okf/drift.py            # что устарело с последнего обновления бандла (от якоря)
python3 scripts/okf/drift.py --branch   # дрейф только текущих изменений (от merge-base с __OKF_BASE_REF__)
python3 scripts/okf/drift.py --gate     # что ветка должна бандлу — это проверяют Stop-хук и CI
python3 scripts/okf/validate_bundle.py okf-bundle   # конформность OKF v0.2 (0 errors)
python3 scripts/okf/graph_check.py okf-bundle       # связность графа (1 компонент, 0 сирот)
python3 scripts/okf/gen_index.py okf-bundle         # перегенерация index.md после добавления концептов
python3 scripts/okf/drift.py --set-anchor           # после рефреша: текущий HEAD — новый якорь
```

Обновление бандла коммить отдельным коммитом `docs(okf): ...` вместе с `okf-bundle/.okf-anchor`. Содержательные правки концептов — по правилам скилла `okf` (обновить `generated.at`, снять устаревший `verified`, дописать запись в `log.md`).

**Параллельные ветки.** Блок okf в `.gitattributes` сливает `log.md` и `.okf-anchor` объединением, а концепты — драйвером `scripts/okf/merge_driver.py`: если обе ветки поменяли дату концепта, остаётся поздняя. Драйвер прописан в `.git/config` клона (SessionStart-хук; клон без Claude Code — один раз `python3 scripts/okf/merge_driver.py --install`). Что после этого остаётся конфликтом:
- `index.md` — не разбирай руками: `python3 scripts/okf/gen_index.py okf-bundle && git add okf-bundle`;
- текст концепта — обе ветки поправили одно место: сведи по смыслу, сохрани факты обеих, затем `validate_bundle.py` (дубль ключа во фронтматтере роняет knowledge-mcp).

Два SHA в `.okf-anchor` после слияния — штатно: `drift.py` считает от первого и изменений другой ветки не теряет, `--set-anchor` на следующем рефреше оставит один. Чтобы правки разных веток не сходились на одной строке — правила записи в скилле `okf` («Merge-friendly»).

Сигналы `drift.py`: **STALE** — источник концепта изменился, перечитать и поправить; **UNCOVERED** — изменённый файл без концепта (новый концепт — только для сущности уровня сервиса/модели); **UNMATCHED** — файл изменился мимо `resource_anchors` своих концептов, проверить вручную; **ORPHANED** — источник исчез, `status: deprecated` или перепривязать; **EXPIRED** — истёк `stale_after`, перепроверить внешний контракт и продлить дату.

**Якоря концептов.** Если один крупный файл описывают несколько концептов, у каждого во фронтматтере `resource_anchors: [Имя, ...]` — символы, которыми он владеет; концепт всплывает, только если правка задела его якорь. Заводя новую модель/экспорт, впиши её в якоря описывающего концепта.

**Новый верхний каталог с кодом.** `paths:` этого файла собраны из `resource:` концептов при последнем запуске `install.py` скилла `okf-repo-setup`; завёл концепт на код в новом каталоге — перезапусти его, иначе правило там не подгрузится.

Фронтматтер обязан быть валидным YAML: значения с `: ` бери в кавычки. `validate_bundle.py` это проверяет.
