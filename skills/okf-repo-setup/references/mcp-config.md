# Настройка `project.ts` у knowledge-mcp

Движок общий; решения о том, **кто что видит**, — в `<mcp-dir>/src/project.ts`.
Это содержательная работа: читай концепты глазами каждой аудитории. Тесты
(`npm test`) проверяют результат на реальном бандле и падают на каждой утечке.

## Порядок

1. **Кто аудитории.** Спроси пользователя, если неясно:
   - заказчик (`partner`) есть всегда — владелец продукта, бизнес-читатель;
   - пользователь продукта (`client`) — только если планируется ИИ-ассистент внутри
     продукта. Нет такого — оставь `clientIds: []`, клиентские тесты пропустятся;
   - `internal` — команда, всё без правок.
2. **Партнёрская поверхность — default-deny.**
   - `allowPrefixes: ['product/']` — продуктовый слой бандла открыт целиком, новые
     фичи становятся отвечаемыми без правки кода.
   - `allowIds` — точечно: `overview`, продуктовые `policy/*`, `reference/glossary`,
     справочники значений, которые заказчик спрашивает. Бизнес-механики, лежащие не в
     `product/` (например, в `services/`), — сюда же, по одной, с комментарием почему.
   - `denyIds` — вырезы из `product/`: внутренние процессы разработки (баг-трекинг,
     деплой), всё про безопасность.
   - Никогда: `ops/`, `api/`, `data/`, `integrations/`, `frontend/`, секреты, env.
3. **Клиентская поверхность — только явный список** `clientIds`, строго подмножество
   партнёрской. Не открывай: экономику и оплату исполнителей/кураторов/менеджеров,
   инструменты команды, точные таблицы лимитов (это чертёж для абьюза механик).
4. **Редактирование.**
   - `repoDirs` — реальные топ-уровневые каталоги репо (`ls`), пути в них будут
     вырезаны. Для Next.js-монолита: `app`, `lib`, `components`, `db`, `scripts`…
   - `sensitive` — проектные идентификаторы: домены проекта, внутренние email, id
     каналов. Движок сам вырезает пути образов в реестрах (`ghcr.io/…`,
     `registry.digitalocean.com/…` и т.п.), @боты и id чатов Telegram. **Внутренний
     домен команды и имена кластеров он не знает** — они в `src/org.ts` (`sensitive`
     и парный `forbidden` для тестов): заполни его, если бандл их упоминает, а
     команда, настраивающая несколько проектов, держит один файл и ставит его
     `install.py --org-file`.
   - `hiddenCategories` — каталоги бандла, чьи голые id нельзя показывать клиенту.
   - `techNouns` — слова стека проекта для клиентского среза (например `Kinescope`,
     `YooKassa`, `iron-session`, `Next.js`).
   - `keepCodes` — коды, которые клиент видит в продукте как есть (`/start`, статусы).
   - `clientHiddenHeadings` — основы заголовков секций, которые клиенту не показывать
     сверх общих технических (например, `оператору` — «Что уходит оператору»).
   - `constantPrefixes` — префиксы UPPER_SNAKE, которые означают константу, а не
     продуктовую метку (например, `RETRY_WINDOW`, `BATCH_LIMIT`). Нужны, когда
     клиентский тест `constant name` ловит утечку вида `RETRY_WINDOW_SEC`.
5. **Поиск.** `synonyms` — как спрашивают люди vs как написан бандл
   (`['оплат', ['платёж', 'enrollment', 'доступ']]`). Добавляй, когда golden-вопрос не
   находит свой концепт, а не заранее.
6. **Тесты.**
   - `partnerMustSee` / `partnerMustHide`, `clientMustSee` / `clientMustHide` —
     по 5–10 id, фиксирующих решения из шагов 2–3.
   - `partnerGolden` — 10–15 реальных вопросов заказчика → допустимые концепты
     (любой из списка в топ-3). Спроси пользователя, что заказчик спрашивает на
     самом деле; если не знает — составь из продуктовых концептов и покажи список.
     Обязателен: пока он пуст, `project.ts` считается незаполненной заготовкой и
     guard-тест `project.ts is configured` валит `npm test`.
   - `clientGolden` — то же для пользователя.
   - `partnerForbidden` / `clientForbidden` — проектные запреты (суммы оплаты
     исполнителям, внутренние названия).
   - `minBodyLength` — порог «раздел выпотрошен редактированием» (400 по умолчанию;
     при коротких концептах снизь, но разберись, почему они короткие).
7. `instructions` — подставь название и суть продукта, для клиента — перечисли темы,
   о которых ассистент может говорить.

## Как чинить падения

- `src/project.ts is still the unconfigured stub` — ожидаемо сразу после установки:
  заполни `project.ts` по шагам выше, golden set заказчика — обязательно.
- `project.ts names concepts that do not exist` — опечатка в id или концепт
  переименован.
- `X leaked in: <id>` — либо поправь концепт (убери хост/путь из прозы), либо добавь
  паттерн в `sensitive`. Не ослабляй тест.
- `<id> was gutted` — клиентское редактирование срезало почти всё: концепт
  инженерный, его не стоит открывать клиенту (убери из `clientIds`), либо в нём
  нет продуктового описания — допиши его в бандл.
- golden-вопрос не находит концепт — сначала проверь title/description/tags концепта
  (поиск весит их сильнее тела), потом `synonyms`.
