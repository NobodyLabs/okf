# okf — бандл знаний о проекте, который не отстаёт от кода

Плагин для [Claude Code](https://code.claude.com/docs). Самостоятельный: ничего не знает
про чужую инфраструктуру, реестры, кластеры и секреты.

**OKF (Open Knowledge Format)** — каталог markdown-файлов с YAML-frontmatter: один файл —
один концепт (сервис, модель данных, эндпоинт, фича, политика), плюс индексы, ссылки между
концептами и источники. Его читают агенты (Claude Code, Codex, Cursor) и новые инженеры,
а через MCP — заказчик продукта.

| Скилл | Что делает |
|---|---|
| `okf` | Пишет, дополняет, обновляет и проверяет бандл по любому источнику: код, API, платформа данных, продукт, документы |
| `okf-repo-setup` | Ставит в репозиторий механику, которая заставляет бандл обновляться вместе с кодом, и — по желанию — MCP-сервер по бандлу для заказчика |

## Установка

```bash
claude plugin marketplace add NobodyLabs/okf
claude plugin install okf@okf
```

Скиллы появятся со следующей сессии: после установки перезапусти Claude Code.

Дальше в сессии, открытой в корне проекта: «задокументируй проект для агентов» (скилл
`okf`) или «настрой okf в репозитории, чтобы бандл не отставал от кода» (скилл
`okf-repo-setup`). Явно — `/okf:okf` и `/okf:okf-repo-setup`.

Обновление:

```bash
claude plugin marketplace update okf
claude plugin update okf@okf
```

## Что ставит `okf-repo-setup`

| Слой | Где в проекте |
|---|---|
| Инструменты: дрейф, валидация, индексы, граф | `scripts/okf/*.py` |
| Stop-хук (не даёт закончить сессию, пока концепты изменённого кода не обновлены) и SessionStart-сводка | `.claude/settings.json` |
| Блок про бандл для всех агентов и правила обслуживания, грузящиеся по путям | `AGENTS.md`, `CLAUDE.md`, `.claude/rules/okf.md` |
| Слияние бандла в параллельных ветках без конфликтов в датах, `log.md` и якоре | `.gitattributes`, `scripts/okf/merge_driver.py` |
| Гейт долга ветки на PR и пуше | `.github/workflows/okf-gate.yml` |
| Стражник для периодической сверки | `.claude/skills/okf-guardian/` |
| MCP-сервер по бандлу (по желанию): аудитории partner / client / internal, редактирование, тесты на утечки, Dockerfile | `knowledge-mcp/` |

Деплой MCP скилл не делает сам: в `skills/okf-repo-setup/references/k8s.md` и
`assets/k8s/` — пример для Helm-чарта, в `references/ci.md` — сборка образа в GitHub
Actions. Реестр, кластер и секреты — ваши.

## Требования

| Что | Зачем |
|---|---|
| Python 3.9+ | все скрипты; только стандартная библиотека (PyYAML — по желанию, включает строгие проверки валидатора) |
| git | дрейф считается по истории |
| Node 24, npm 11+ | только для MCP-сервера |
| GitHub Actions | гейт и сниппеты CI написаны под него; хуки и скрипты от него не зависят |

## Что стоит знать заранее

- **Язык.** Скилл `okf` и спецификация — на английском. Всё, что `okf-repo-setup`
  кладёт в проект (сообщения хука и `drift.py`, правила, стражник, README и инструкции
  MCP-сервера), — на русском.
- **Редактирование для заказчика.** Движок MCP сам вырезает пути в репозитории, пути
  образов в реестрах, Telegram-ботов и id чатов. Внутренний домен и имена кластеров
  вашей команды он не знает — впишите их в `knowledge-mcp/src/org.ts` (один файл на
  команду, ставится `install.py --org-file`), проектное — в `src/project.ts`. Тесты
  сервиса гоняются по настоящему бандлу и падают на каждой утечке.
- **Привязка к стандарту команды.** Если у команды есть свой скилл сетапа проектов,
  `okf-repo-setup` загрузит его и возьмёт оттуда привязку к CI, деплою и секретам.

## Про этот репозиторий

Это зеркало: его содержимое собирается автоматически при каждом релизе плагина, по
одному коммиту на версию. Вопросы и ошибки — в issues. Pull request'ы читаем, но
принять кнопкой не можем: правку переносим в исходный репозиторий руками, и она
приходит сюда со следующим релизом.
